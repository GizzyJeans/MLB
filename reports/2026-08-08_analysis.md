## 1. 為什麼是「不下注」，而不是「今天沒好球」

這不是邊際判斷，是結構性阻斷。三個獨立的理由，任何一個都足以否決：

**(a) 無法建立得分分布。** 本環境的網路政策封鎖了所有棒球資料來源。可連線的
只有賠率 API 與 GitHub：

| 來源 | 狀態 |
|---|---|
| `statsapi.mlb.com`（賽程／先發／打線） | 封鎖 |
| `baseballsavant.mlb.com`（Statcast） | 封鎖 |
| `fangraphs.com`／`baseball-reference.com` | 封鎖 |
| `rotowire.com`／`mlb.com`／`espn.com`（打線） | 封鎖 |
| `api.weather.gov`／`open-meteo.com`（天氣） | 封鎖 |
| `api.the-odds-api.com`（賠率） | **可用** |

沒有先發投手數據、打線、牛棚使用量、球場與天氣，就無法估計兩隊的期望得分，
也就沒有模型機率。指令明確要求「必須建立主客隊得分分布」——這一步做不到。

**(b) 正式打線尚未公布。** 現在是 11:45 AM ET，最早的比賽 3:05 PM ET 開打，
打線一般在開賽前約 2 小時才公布。依規則，今天此刻的所有內容只能標示為
**觀察**，不得給出最終投注指令。

**(c) 即使有投手名字也不夠。** 透過搜尋取得了 4 場的先發投手片段（見下），但
**無法驗證**，且沒有任何 2026 球季的數據可以配上這些名字——本模型的知識截止於
2026 年 1 月，而所有數據站都被封鎖。知道「佐佐木朗希先發」在沒有 2026 年
球速、球種、xFIP 的情況下，不構成量化輸入。我不會用記憶或推測填補這些數字。

## 2. 市場掃描結果（這部分資料是真實且完整的）

15 場比賽 × 16 家莊家，共 78 個已定價盤口。以「其他所有莊家的去水共識中位數」
為基準（leave-one-out，避免離群莊家自己決定自己的基準）：

| 門檻 | 通過數 |
|---|---|
| EV ≥ +4%（指令門檻） | **0 / 78** |
| EV ≥ +3% | 0 / 78 |
| EV ≥ +2% | 1 / 78 |
| EV > 0 | 8 / 78 |

**全盤最佳者：Boston Red Sox -1.5 @ -115（hardrockbet），對比共識公平價 -122，
市場相對 EV +2.81%（15 家莊家）。** 仍低於 +4% 門檻，且這是「相對市場共識」的
價差，不是模型優勢——指令要求的是模型機率與去水市場機率相差 3 個百分點，
而模型機率不存在。

### 一個必須說清楚的偏誤

78 個最佳報價中有 52 個來自 hardrockbet／hardrockbet_oh。原因不是它們定價失準，
而是它們的抽水最低：

| 莊家 | 抽水（大小分中位數） |
|---|---|
| hardrockbet_oh | 2.27% |
| hardrockbet | 2.38% |
| lowvig | 3.49% |
| 多數其他莊家 | 4.71% |
| fliff | 5.76% |

低抽水莊家在幾乎每一條線上都提供最好的價格。那是「票價便宜」，不是「盤口有誤」。
把它當成優勢會系統性高估自己的勝率。此外，Hard Rock 僅在部分美國州別提供服務，
使用者是否實際可下注需自行確認——「實際能取得的最佳價格」可能與此表不同。

## 5. 恢復運作需要什麼

模型引擎（`src/mlbline/rundist.py`）已實作、已校準、已通過測試，缺的只有輸入。
只要放行下列任一組來源，整條管線即可運作：

1. `statsapi.mlb.com` — 賽程、先發、正式打線、傷兵（免費、無需金鑰）
2. `baseballsavant.mlb.com` — Statcast、投手球種與球速
3. 任一天氣 API — 溫度、風向、濕度、屋頂狀態
4. Odds API 付費方案 — 開盤盤口與盤口移動歷史

或者由使用者直接提供每隊的期望得分，模型即可輸出各盤口機率：

```python
from mlbline.rundist import simulate_game
sim = simulate_game(expected_home_runs=4.9, expected_away_runs=4.1)
sim.prob_cover(-1.5, home=True); sim.prob_over(8.5)
```

## 6. 追加：跨市場衍生定價（不需球隊基本面）

拿到先發投手後仍缺 2026 數據，但有一條路不需要基本面：**錢線與大小盤共同決定了
得分結構，Run Line 因此不是自由參數，而是衍生品。**

作法：對每場比賽去水後取 P(主勝) 與 P(大)，用二維求解反推兩隊期望得分，再用已
校準的模擬器推導 Run Line 應有價格，與實際盤口比較。求解器經 round-trip 驗證
（已知 λ → 市場機率 → 反解），殘差 < 0.4pp，回推的 Run Line 機率誤差 < 0.4pp。

初次結果看似有料 —— Athletics +1.5 @ +120 顯示 +4.49pp 分歧、EV +8.89%，同時
超過 3pp 與 +4% 兩個門檻。**但它是假的。**

### 為什麼判定為模型假訊號

**九場比賽，九場全部同向。** 每一個熱門的 -1.5 都被模型判為偏低，每一個冷門的
+1.5 都被判為偏高，無一例外：

| 側 | 原始分歧 | 去偏後殘差 |
|---|---|---|
| BOS -1.5 | −4.62pp | −1.85pp |
| SD -1.5 | −3.32pp | −0.55pp |
| MIL -1.5 | −3.14pp | −0.37pp |
| SEA -1.5 | −2.71pp | +0.06pp |
| TEX -1.5 | −2.56pp | +0.21pp |
| MIA -1.5 | −2.54pp | +0.23pp |
| PIT -1.5 | −2.28pp | +0.49pp |
| PHI -1.5 | −1.99pp | +0.78pp |
| STL -1.5 | −1.81pp | +0.96pp |

平均偏誤 **−2.77pp**，殘差標準差僅 **0.80pp**。也就是說，全部分歧幾乎可以用「一個
固定常數」解釋完畢，沒有任何一場有球隊專屬的訊號。真實的市場失效是零散、雙向的；
整個賽程單一方向的分歧是模型設定錯誤的特徵，不是九個獨立的價值。

**找到了成因。** 模擬器產生 **31.0% 的一分差比賽，實際 MLB 約 28.5%**。一分差
比賽過多，機械性地壓低每個熱門隊「贏 2 分以上」的機率。主隊「贏2+/獲勝」比值
模型給 62.5%。

**而且這個參數校不準。** 兩個聯盟級錨點互相衝突：

- dispersion 0.43 → 得分變異數/均值 = 2.14（實際 2.15 ✓），但一分差 31.0% ✗
- dispersion 0.35 → 一分差 29.9%（較接近 ✓），但變異數/均值 = 2.41 ✗

在合理參數範圍內，平手局面的 P(主 −1.5) 在 **29.8%–32.8%** 之間游走 —— 約 3pp
的帶寬，跟我找到的「優勢」同一個數量級。結構性原因：本模型各局獨立抽樣、兩隊
得分不相關，而真實比賽兩者都不成立（同一投手投多局、打線輪轉、牛棚隨比分調度），
所以得分分布對了、分差分布仍然太緊。要根治需要改用 base-out 狀態馬可夫鏈。

**去偏後最大殘差 1.85pp < 3pp 門檻，全部不通過。** 這個限制已寫進
`rundist.py` 的註解與兩個測試，避免日後被無聲地忽略。

## 7. 追加：實際嘗試抓取投手數據的結果

WebSearch 這條路確實是通的（走 Anthropic 的檢索基礎設施，不經過 egress proxy），
所以有系統地跑了一輪。結果如下。

**可以拿到的：** 個別投手的 ERA、勝敗、三振數。例如 Sale 2026 ERA 2.06、111 IP、
K% 29%；Cole 因 2025 年 Tommy John 手術缺陣、2026 年 5 月底才回歸，約 68 IP。

**問題在精度。** 同一天、同一名投手，不同來源給出的數字互相矛盾：

| 投手 | 來源 A | 來源 B | 來源 C |
|---|---|---|---|
| Cole ERA | 3.42（78 K） | 3.92（62 IP, 66 K） | 3.57（68 IP, 73 K） |
| Sale | 2.08 / 143 K | 2.06 / 123 K / 111 IP | — |

**團隊打擊數據幾乎抓不到。** 30 隊只湊到 3 個數字（國民 5.36、守護者 4.05、
勇士 4.76 且註明「截至 6 月底」），且無統一時間戳。牛棚使用量、天氣、左右打
分項則完全沒有。

**所有數據站在網路層被擋。** 逐一測試 statmuse、foxsports、cbssports、si、
fantasyteamadvice、yardbarker、teamrankings、lineups、weather API —— 全部回
`000`（連線遭拒），不是抓取失敗，是連不上。

### 精度預算：為什麼這些數據不夠用

要分辨 3pp 的 Run Line 優勢，期望得分需要多準？

| 主隊期望得分偏移 | P(主 −1.5) 移動 |
|---|---|
| +0.10 分 | +0.91pp |
| +0.20 分 | +1.75pp |
| +0.30 分 | +2.56pp |
| +0.50 分 | +4.23pp |

**誤差預算約 ±0.35 分。** 而單是 Cole 的 ERA 在三個來源間差 0.50，換算成他主投
六局的期望失分就是 **±0.33 分 → 2.93pp**。**一名投手的資料歧異就吃掉幾乎整個
誤差預算**，還沒開始算對手打線（30 隊缺 27 隊）、牛棚、天氣、左右對位、輪休。

這不是「資料少一點但可以將就」，是**訊號小於雜訊**。用這種輸入產出的「模型機率」
會是隨機數，而它會長得跟真的一模一樣——這正是量化模型最危險的失效模式。

## 8. 引擎升級：base-out 馬可夫鏈

第 6 節指出的模型缺陷已修好。診斷顯示超出的機率質量**幾乎全部集中在 margin=1**
（+2.5pp），其餘各檔都接近實際——這是把再見分數硬編碼成「+1 分，20% 機率多得
1~3 分」造成的堆積。

新引擎逐個打席推進 8 種壘包狀態 × 3 種出局數，因此**不需要再見規則**：得分超前
的瞬間比賽自然結束，再見安打得 1 分、滿貫全壘打得 4 分，比例由打擊事件本身決定。
分差分布從「輸入」變成「輸出」。

**校準結果：**

| 半局得分 | 模型 | 實際 |
|---|---|---|
| 0 分 | 72.2% | 72.7% |
| 1 分 | 15.3% | 15.0% |
| 2 分 | 7.0% | 6.4% |

以真實對戰強度分布混合後，分差分布的總絕對誤差從舊引擎的 **5.05pp 降到 3.42pp**。

**對 Run Line 定價的影響：**

| | 舊（半局抽樣） | 新（馬可夫） |
|---|---|---|
| 樣本場次 | 9 | **14** |
| 平均偏誤 | −2.77pp | **−1.44pp** |
| 同向比例 | 9/9 | 14/14 |
| 去偏後最大殘差 | 1.85pp | 2.46pp |

**偏誤減半。** 同時修掉另一個抽樣偏誤：先前把讓分盤寫死成「主隊 −1.5」，導致
**所有客隊為熱門的比賽被靜默跳過**（勇士、紅人、小熊、守護者、道奇等 6 場）——
那不是樣本變小，是樣本有偏。現在依市場實際掛盤方向取用。

**但仍然 14/14 同向**，代表還有殘餘偏誤。方向與已知的殘留校準誤差一致（一分差
比例仍高約 1pp）。也可能有一部分是市場本身的結構性偏好（散戶偏愛熱門隊的
plus-money 讓分），但在沒有樣本外驗證前，最簡約的解釋仍是我的模型。

**去偏後最大殘差 2.46pp < 3pp 門檻 —— 全部不通過。** 最佳者 Athletics +1.5
@ +120 的 EV 從 +8.89% 降到 +7.30%，但去偏後分歧僅 2.46pp，未達標。
