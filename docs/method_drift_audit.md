# 前瞻測試開始後勝率下降：方法有沒有改？

**稽核日期：2026-09-16**

## 問題

08-29（前瞻測試起算日）之前 200 筆平均 +5.49%、勝率 54.8%；
之後 150 筆平均 −14.91%、勝率 43.5%。差 20.40pp。

方法是不是在那個時間點改了？

## 結論

**沒有。定價與選取的邏輯在 08-29 沒有任何改動，之後也沒有。**

## 一、程式碼稽核

08-29 那個 commit（e0b29db）只動了輸出：

```
-    candidates.sort(key=lambda c: -c["adj"])
+    a = ranking("adj", ...)   # 同一批候選、同一個排序鍵
+    b = ranking("raw", ...)   # 新增的第二份排序，不產生任何推薦
+    candidates = a
```

`sort` 與 `sorted` 都是穩定排序，A 組的順序與改動前逐筆相同。被記錄成
「當日推薦」的一直是 A 組。

**08-29 之後，`src/` 與 `scripts/price_board.py` 的 commit 數是 0。**

所有實質性的定價改動都在視窗開始之前：

| 日期 | 改動 | 位置 |
|---|---|---|
| 08-16 | 引入 `COVER_BIAS` 去偏修正 | 視窗前 13 天 |
| 08-20 | 大小盤改為多錨點加權擬合 | 視窗前 9 天 |
| 08-24 | 修正錨點殘差診斷（當時已驗證不改動任何 EV） | 視窗前 5 天 |
| 08-25 | 公平讓球改用 `comparable_handicap` 顯示（純顯示） | 視窗前 4 天 |
| 08-29 | 印出第二份排序（純顯示） | 視窗起點 |

### 實測驗證（2026-09-16）

不只看 diff。把 08-29 之前的 `price_board.py` 原封取出，用**現行的 `src/`**
（自 08-25 未改）重跑 09-15 的板面：

- 解碼驗證表、上半場一致性檢查、EV 分布、門檻計數 **全部逐行 0 差異**
- 整份報告唯一的差別，是舊版少印了 B 組那 13 行

**回退到 08-29 之前的版本，會改變 0 筆推薦。**

這條規則（讀行與美盤衝突時採美盤方向）確實改變了輸入，但它實際只翻動
兩場比賽：

## 三、真正改變的是板面，不是方法

| | 08-29 前 | 08-29 後 |
|---|---|---|
| 平均事前預期 EV | −0.13% | +0.33% |
| 讓球 / 大小 | 121 / 79 | 82 / 68 |
| 讓分 / 受讓 | 55 / 66 | 45 / 37 |
| 每日板面場數 | 12.6（7~15） | 13.1（7~16） |

受讓方的比例從 66/121 降到 37/82。這些是板面掛什麼線決定的，不是選取
規則決定的——同一套排序餵進不同的板面，自然會吐出不同的組成。

## 四、那 20.40pp 的落差本身站得住嗎？

單看那個切點：t = +2.04，雙尾 p ≈ 0.04，重排檢定 4.3%。看起來顯著。

**但那個切點是看著資料挑的。** 正確的虛無假設不是「08-29 這個特定切點」，
而是「在 35 天的序列裡任意找一個切點」。

把同樣 35 天隨機重排，再問「是否仍存在某個切點，落差 ≥ 20.40pp」：

**44.0%**

實際序列裡最大的落差是 23.17pp，切在 08-28——幾乎就是同一個位置，因為
那正是被注意到的地方。

而且兩期各自都沒有拒絕「沒有優勢」：

| | 平均 | 對抽水 −2.6% 的 t |
|---|---|---|
| 08-29 前 | +5.49% ± 6.67% | +1.22 |
| 08-29 後 | −14.91% ± 7.43% | −1.66 |

兩邊都不顯著。前段不是「有優勢」，後段也不是「變差了」——**是同一個沒有
訊號的過程的兩個區段。**

## 五、這件事本身的意義

值得注意的不是勝率掉了，而是**這是一個在無訊號序列上必然會出現、而且
必然會誘人去解釋的現象**。如果當初因為 08-29 之後表現變差而去「修正」
模型，那就是在對雜訊做曲線擬合，而且會留下一個看起來有理由的改動紀錄。

方法沒有改，是這次能乾淨回答這個問題的唯一原因。
